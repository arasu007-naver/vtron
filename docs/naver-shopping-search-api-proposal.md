## 2. 서비스 소개

STMX 는 사용자가 반복해서 좋아하는 옷차림의 이유를 찾아 주는 패션 서비스다.

- **Style ID** — 설문과 사진으로 사용자의 스타일 코드를 진단한다.
- **LOOX** — 사용자가 자기 착장(룩) 사진을 올리고, 같은 스타일 코드를 가진 사람들의 룩을
  피드로 본다. 좋아요 · 댓글 · 팔로우 · 스타일 매치 기능을 갖춘 이미지 커뮤니티다.

LOOX 게시물을 본 사용자가 가장 많이 묻는 것은 "이 옷 어디서 사요?" 다. 이번 제휴는 그 질문에
네이버 쇼핑으로 답하기 위한 것이다.

## 3. 제휴 목적 — '착장 확인하기'

LOOX 게시물 상세 화면의 **'착장 확인하기'** 단추를 누르면, 그 룩에 쓰인 상품이 카드로
뜬다(브랜드 · 상품명 · 가격 · 대표 이미지). 카드를 누르면 **"네이버 쇼핑으로 이동합니다."**
확인을 거쳐 네이버 쇼핑 상품 페이지로 이동한다.

```
LOOX 게시물 ──[착장 확인하기]──▶ 착장 상품 카드 목록 ──[카드 선택]──▶ 이동 확인 ──▶ 네이버 쇼핑
                                  (이미지 · 상품명 · 가격)                          (search.shopping.naver.com)
```

- 게시물 하나에 상품 여러 개를 걸 수 있다.
- 구매는 전부 네이버 쇼핑에서 일어난다. STMX 는 결제 · 판매를 하지 않는다.

## 4. API 활용 방안

| 항목 | 내용 |
| --- | --- |
| 사용 API | 검색 > 쇼핑 (`GET https://openapi.naver.com/v1/search/shop.json`) |
| 요청 | `query` = 브랜드명 + 상품(모델)명, `display` ≤ 20, `sort=sim` |
| 사용 필드 | `title`, `image`, `lprice`, `link`, `productId`, `mallName` |
| 호출 위치 | **서버에서만** 호출한다. Client Secret 은 브라우저로 내려가지 않는다. |
| 호출 시점 | 운영자가 게시물에 상품을 연결할 때(운영 도구). 일반 사용자의 화면 조회가 API 를 직접 부르지 않는다. |

상품은 네이버 커머스 API 의 카탈로그 모델(`/v1/product-models`)로 먼저 특정한다. 카탈로그
모델에는 이미지 · 가격이 없어, 같은 카탈로그(`productId` = 모델 id)의 쇼핑 검색 결과에서
대표 이미지와 최저가를 가져와 카드에 쓴다.

## 5. 표시 및 준수 사항

- 카드에 **네이버 쇼핑 출처**를 표기하고, 이동 전 "네이버 쇼핑으로 이동합니다." 로 한 번 알린다.
- 링크는 네이버 도메인(`https`, `*.naver.com` / `naver.me`)만 허용한다 — DB 제약과 화면
  검증을 이중으로 둔다. 임의의 외부 사이트로 보내지 않는다.
- 이미지 · 상품명은 변형 없이 그대로 쓴다.
- 가격은 [갱신 주기, 예: 매일 1회] 다시 조회해 맞춘다. 품절은 카드에 'SOLD OUT' 으로 표시한다.
- 사용자 개인정보는 API 요청에 담지 않는다(검색어는 상품명뿐).
- [API 이용약관의 저장 · 캐시 조건에 맞춘 보관 기간/방식 기재]

## 7. 기대 효과

- **네이버 쇼핑** — 구매 의도가 분명한 패션 트래픽이 네이버 쇼핑 상품 페이지로 바로 유입된다.
  STMX 는 룩 사진 → 상품이라는 발견 단계를 맡고, 구매는 네이버 쇼핑에서 끝난다.
- **사용자** — 마음에 든 룩의 상품을 검색 없이 한 번에 찾는다.
