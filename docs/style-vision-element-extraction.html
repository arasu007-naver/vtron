STAGE 2 · B

적용성 결정 — 어떤 키를 낼 것인가

키를 생략하는 것은 "해당 없음"을 뜻하는 계약입니다. "안 보임"을 생략으로 표현하면 안 됩니다.

NOT-APPLICABLE

카테고리별 금지 키 → 키 자체를 생략

ABSENT·None·N/A·null로도 내보내면 안 됨. 예: Trouser의 closure_type, Jacket의 shoulder_span, 상의의 silhouette.

REQUIRED KEYS

카테고리별 필수 키 → 반드시 존재

없는 특징도 None/ABSENT로 답함. 개수: T-Shirt·Shirt 19 · Sweater·Sweatshirt 20 · Jacket·Coat·Jumpsuit 21 · Trouser·Skirt 14 · Dress 23.

CONDITIONAL TRIGGERS

부모 관찰이 켜면 반드시 따라 나오는 키

  • front_opening_extent = Partial/Full → closure_type (Jacket/Coat는 항상 필수) #2
  • sleeve ≠ Sleeveless → cuff_type, sleeve_volume
  • cuff_type ≠ None → cuff_scale (None이면 키 생략)
  • collar ≠ None → collar_scale
  • 스트랩·스트랩리스·홀터·원숄더가 보이면 → shoulder_connection #4
  • waist_definition: 게이트1 Jacket/Coat/Dress/Jumpsuit · 게이트2 Jacket이 Cropped/Waist Length면 제외 #3
개선 #2앞트임 없는 아우터의 closure_type Jacket/Coat에서는 필수인데 값 도메인에 None이 없어, 앞트임이 없는 아노락(front_opening_extent=None)에 쓸 정상 답이 없다. 아우터에서도 Partial/Full일 때만 쓰는 조건부 키로 바꾸거나, 이 경우 ABSENT를 쓴다고 명시한다.(원문: “closure_type … emit it on Jacket / Coat (their closure), and on a T-Shirt / Shirt / Sweater / Sweatshirt / Dress / Jumpsuit that has a visible FRONT OPENING” / “- closure_type: Button | Single Breasted Button | Double Breasted Button | Snap Button | Zipper | Hook Closure | Open”)

  • CATEGORY SYNTHESIS DISCIPLINE: 카테고리는 몸판 원단/구조, 드레이프와 자립성 같은 거동, 트림, 착용 역할을 함께 보고 종합해 정함. 단일 특징으로는 절대 정하지 않음. zipper는 여밈 장치, hood는 부착물, 민소매는 소매 사실, collar는 목 사실일 뿐임.
  • KNIT-BODY RULE: 몸판이 니트(rib/cable/chunky)이고 니트 거동과 니트 트림을 가지면 Sweater. 카디건과 풀집업 니트 카디건도 포함됨. Jacket이 되려면 아우터웨어 셸(테일러드/우븐/테크니컬/가죽)이 있어야 함.
  • SWEAT-BODY RULE: 몸판이 스웨트/플리스이고 립 트림이 있으면 Sweatshirt. 집업 후디도 Jacket이 아님.
  • OUTERWEAR-COLUMN RULE: 무겁고 자립하는 외투 원단, 전장 앞트임, 아우터 칼라와 포켓을 갖춘 긴 옷은 Coat(민소매여도 Dress가 아님). 반대로 몸 레이어로 입는 부드럽게 흐르는 원피스는 길어도 Dress. 원단 무게, 자립성, 트임, 역할로 판단함.
  • category.evidence는 필수이며 구조 단서를 최소 2개 적어야 함. 비어 있으면 불완전한 관찰임.
  • 확정할 수 없으면 category.state = "UNKNOWN"으로 두고 범용 파라미터 9개(material, surface, pattern, graphic, pocket, decorative_detail, attachment, asymmetry, exposure_opening)만 관찰함.

[GARMENT TARGET SELECTION — GARMENT items only]

  • 대상은 GARMENT뿐임. 신발, 가방, 주얼리, 액세서리용 벨트, 안경, 모자, 장갑, 액세서리용 스카프 등은 대상이 아님.
  • identity: 독립적으로 식별 가능한 의류인지(C2 Independent Identity) true/false와 짧은 근거로 보고함.
  • readability(C3): 질문은 "의류 전체 형태를 독립 타깃으로 재구성할 수 있을 만큼 구조가 보이는가?"임. 형식은 {value, basis: RECONSTRUCTABLE|NOT_RECONSTRUCTABLE, limitation, evidence}. eligibility는 basis만으로 정해지고 value와 일치해야 함. limitation(TERMINAL_REGION_CROPPED · FRAGMENTARY_VISIBILITY · OCCLUDED_BY_OTHER_GARMENT · CONTINUOUS_STRUCTURE_VISIBLE)은 설명용일 뿐 결정에 쓰이지 않음.
  • C3가 아닌 것: 카테고리 식별 가능, 일부 국소 속성(waistband, pocket, neckline, sleeve, material, silhouette, length) 관찰 가능, 관찰 파라미터 개수. 디테일이 많이 보여도 NOT_RECONSTRUCTABLE일 수 있음.
  • 반대로 부분적으로 안 보인다고 자동으로 false가 되지도 않음. 연속된 몸판, 볼륨, 드레이프, 비례가 보이면 RECONSTRUCTABLE. 같은 limitation이 어느 결론으로든 이어질 수 있음.
  • prominence: dominant / secondary / minor. 장면 내 역할만 나타내며 eligibility를 정하지 않음.
  • 예시 1: 엉덩이까지만 보이는 바지는 다리 전체 형태를 재구성할 수 없으므로 NOT_RECONSTRUCTABLE. 하드웨어가 읽힌다고 전체 형태가 되는 것은 아님.
  • 예시 2: 밑단이 잘린 드레스라도 연속된 몸판이 잘 읽히면 RECONSTRUCTABLE + TERMINAL_REGION_CROPPED.
  • 예시 3: 열린 코트 안의 이너는 NOT_RECONSTRUCTABLE + OCCLUDED_BY_OTHER_GARMENT.
  • PRODUCT-DEFINING STRUCTURE TEST: 고정부(하의는 허리, 매달리는 옷은 서스펜션)와 끝에서 끝까지의 실루엣이 덮는 옷에 가려 끊기면 NOT_RECONSTRUCTABLE. 큰 조각이 보여도 결과는 같음. 프레임 크롭과는 구분함.
  • READABILITY SELF-CONSISTENCY: 자기 서술에 "entirely hidden", "cannot be traced"가 있으면 RECONSTRUCTABLE은 모순이므로 내보내면 안 됨. 아이템 병합, 숨은 의류 추론 금지. "Multiple garments"는 한 룩 안의 여러 아이템을 뜻함.

[STATES — use the correct one; never invent a value to avoid UNKNOWN]

  • OBSERVED: 특징이 있고 값을 판별할 수 있음. 값이 필수이며, 도메인에 "None"이 있으면 유효한 값임.
  • ABSENT: 해당되고 보이지만 특징이 없음(value null). SV-5 PRIORITY RULE: 도메인에 None이 있는 파라미터라면 OBSERVED "None"으로 적음. 가시성이 나쁜 경우에는 None이 아니라 NOT_VISIBLE/UNKNOWN을 씀.
  • NOT_VISIBLE: 가림·크롭·프레임 밖. UNKNOWN: 보이지만 판별 불가. 모호함을 ABSENT로, 가림을 UNKNOWN으로 바꾸지 않음. UNKNOWN에 값을 추측해 넣지 않음.
  • OBSERVED에는 값이 반드시 있어야 함. 값을 대지 못하면 UNKNOWN을 씀.
  • EVIDENCE–VALUE CONSISTENCY: evidence가 값을 부정하면 OBSERVED로 내보내지 않고 부재 상태로 바꿈.
  • CONDITIONAL COMPLETENESS RE-CHECK: 트리거된 조건부 파라미터는 반드시 보고함. closure_type(Partial/Full 앞트임), cuff_type(소매 끝이 보일 때, 커프가 없으면 "None"), cuff_scale(non-None 커프일 때만, cuff_type="None"이면 키 생략), shoulder_connection(비표준 서스펜션), waist_definition(TWO GATES). 누락은 계약 위반임.
  • TRIGGERED-KEY EMISSION FINAL SWEEP은 마지막 기계적 게이트로, 작성한 JSON 키를 실제로 점검함. (1) 민소매가 아닌 sleeve인데 cuff_type 없음 (2) Partial/Full인데 closure_type 없음 (3) cuff_scale (4) collar가 non-None인데 collar_scale 없음 (5) pocket Present이면 pockets[]가 비어 있지 않아야 하고 각 그룹에 location/construction/projection이 있어야 함. top-level pocket_construction/pocket_projection은 폐기됨 (6) sleeve_volume (7) Jacket/Coat/Dress/Jumpsuit에서 gate를 통과하면 waist_definition. Trouser/Skirt, Jacket "Cropped"/"Waist Length"에는 금지. 서술에 언급한 특징은 구조화 키에도 있어야 하며, 누락은 validator 실패로 처리됨.
  • 라우팅: 외곽 레이어로 입는 셔츠 칼라 옷(overshirt/shacket 등)은 Jacket. "Overshirt" 카테고리를 새로 만들지 않음.
  • 적용되지 않는 파라미터는 생략함(None으로 내보내지 않음). grammar는 Jacket/Coat 전용. closure_type은 Jacket/Coat에 쓰고, 그 외 상의/Dress/Jumpsuit는 앞트임이 있을 때만 쓰며 Trouser/Skirt에는 금지. shoulder_structure는 Outerwear/Dress/Jumpsuit.
  • shoulder_drop은 아우터웨어에서도 필수. shoulder_structure(윤곽 형태)와는 독립적이며 None+Dropped, Strong+None 모두 유효함.
  • slit은 Skirt/Dress 전용. exposure_opening은 모든 카테고리에서 필수 키임(크롭티, 미니스커트, 시스루 셔츠 등도 해당). 노출이 없으면 ABSENT, 판단할 수 없으면 NOT_VISIBLE/UNKNOWN.
  • Jacket/Coat에는 neckline_shape/position을 쓰지 않음(collar로 표현). 이 규칙은 카테고리 기준이므로, 칼라가 있는 다른 카테고리에서는 neckline도 필수임.
  • front_opening_extent는 아우터웨어에서 필수(Full/Partial/None). 확장 범위를 보고하며 closure_type(메커니즘)과는 독립적임. 예: half-zip = Zipper + Partial.
  • Trouser/Skirt에는 waist_definition을 쓰지 않음. silhouette는 Trouser/Skirt/Dress/Jumpsuit 전용이며 다른 카테고리에서는 키 자체가 없어야 함.
  • shoulder_connection/shoulder_span은 일반 소매 옷에 강제하지 않음. 비표준 서스펜션(Strap/Strapless/Halter/One Shoulder)을 인지하면 필수로 OBSERVED 처리함.
  • ruffle(None/Present)은 Dress 전용. 러플 칼라는 collar = Ruffle, 러플 스커트는 surface = Gathered, 플리츠는 Pleated로 적음.

[SEMANTIC None — WHICH PARAMETERS REQUIRE IT (SV-5)]

  • 아래 파라미터는 도메인에 None이 있으므로, 확인된 부재를 OBSERVED "None"으로 보고함.
  • T-Shirt/Shirt/Sweater/Sweatshirt: shoulder_drop, collar, cuff_type, rib_hem, front_opening_extent, pocket, asymmetry.
  • Jacket/Coat/Jumpsuit: 위 목록 + shoulder_structure.
  • Trouser: pocket, asymmetry. Skirt: pocket, asymmetry, slit. Dress: Jacket 목록 + slit, ruffle.
  • 부재가 확인되면 키 생략, ABSENT, NOT_VISIBLE, UNKNOWN 모두 금지. { "state": "OBSERVED", "value": "None", "evidence": [...] }로 적음.
  • 예시(hem): 평범한 동일 원단 마감이면 OBSERVED/"None", 가방에 가리거나 크롭되면 NOT_VISIBLE, 해상도가 낮으면 UNKNOWN.
  • 확인된 부재는 관찰 실패가 아니라 긍정적 관찰이며, 침묵이 아니라 None으로 기록함.

[REGIONS]

  • 허용 토큰: whole_garment | upper | lower. 자연어 region은 쓰지 않음.
  • upper: sleeve, sleeve_volume, shoulder_connection, shoulder_span, shoulder_drop, shoulder_structure, neckline_shape, neckline_position, collar, collar_scale, cuff_type, cuff_scale, rib_hem, hood, front_opening_extent, closure_type.
  • rib_hem은 하단에 있어도 upper이며 짝이 되는 cuff 필드가 없음. 립 커프는 cuff_type = Ribbed로 적음.
  • lower: slit.
  • fit: 상의/아우터 upper, Trouser/Skirt lower, Dress/Jumpsuit upper+lower. length: 상의/아우터 upper, Trouser/Skirt/Jumpsuit lower, Dress whole_garment.
  • fabric_behavior: whole_garment이며 Dress/Jumpsuit만 upper+lower(byRegion).
  • 나머지(silhouette, material 포함)는 하의를 포함한 모든 카테고리에서 whole_garment. 목록에 없는 region은 지어내지 않음.
  • 두 region을 쓰는 파라미터는 "byRegion": { "upper": {...}, "lower": {...} } 형식을 씀.

[LOCATION — optional per-value garment component binding]

  • 선택 사항. material / surface / decorative_detail / attachment 값에만 locations를 붙일 수 있음. exposure_opening에는 붙이지 않음.
  • Component 토큰: Body · Bodice · Skirt Body · Leg · Shoulder · Sleeve · Collar · Lapel · Hood · Cuff · Hem · Waistband · Pocket · Strap.
  • 헷갈리기 쉬운 구분: Body는 상의/아우터 몸판, Bodice는 Dress/Jumpsuit 상체, Skirt Body는 스커트 부분("Skirt" 금지), Leg(Thigh/Knee 등 금지), Hem은 하단 마감(바지 밑단 포함), Cuff는 실제 커프 구조가 있을 때만, Shoulder는 위치일 뿐 어깨 파라미터에 영향 없음.
  • descriptor는 두 가지뿐임. "Panel"(반드시 component와 함께), "Edge"(component와 함께 또는 단독).
  • 예시: Jacket Glossy→Lapel, Dress Lace→Bodice, Trouser 밑단 Lace→Hem. 여러 component는 한 값 항목에 함께 넣음. Piping→{"descriptor":"Edge"}.
  • 규칙: 지어내지 않음. 전체에 해당하면 생략("Whole Garment" 없음). Front/Back/Left/Right/Upper/Lower/Side/Center 같은 좌표 단어 금지. 같은 값을 반복하지 않음. 크기·중요도 표현에 쓰지 않음. region과는 별개임.

[COVERAGE — optional per-value garment extent]

  • 선택 사항. 값이 의류의 얼마만큼을 덮는지를 나타냄.
  • 다음 값에만 허용됨. surface: Transparent · Semi Transparent · Mesh · Reflective · Glossy · Textured Knit · Exotic-Skin · Quilted · Treated Surface · Pleated · Lace / material: Fur / decorative_detail: Sequin-Beading · Appliqué / attachment: Metal Hardware · Jewelry Attachment · Feather · Ribbon · Fringe · Fur Trim. 그 외(Cotton, Wool, Belt, Embroidery, Piping, Gathered 등)에 붙이면 계약 오류임.
  • 값은 Localized(제한된 부분), Partial(상당 부분이지만 지배적이지 않음), Dominant(대부분/전체의 성격) 세 가지뿐임.
  • coverage는 location이 아님. 둘은 서로를 함축하지 않으며 함께 쓸 수 있음(예: Glossy lapel = Lapel + Localized).
  • 보이는 것만 보고함. 수치나 프레임 밖 추정은 금지이며, 판단할 수 없으면 생략함.
  • 중요도 판단이 아님. Weak/Strong, I/Neutral/E, Small/Large/Full/Global 등은 금지.
  • OBSERVED 값에만 붙임. 값마다 따로 붙이고(예: Quilted Dominant + Fur Trim Localized) 의류 전체에 하나만 붙이지 않음.
  • 예시: Glossy Localized+Lapel, Quilted Dominant, Metal Hardware Partial, Fur Localized+Collar. Wool에 coverage를 붙이면 오류임.
  • graphic(자체 값에 범위가 포함됨), pattern(정의상 전체), exposure_opening에는 쓰지 않음.

[POCKET — observe independently; no inference]

  • 기본 관찰: pocket(None/Present)을 관찰한다. Present이고 판독 가능할 때만 다음 두 값을 본다.
    • pocket_construction: Inset(set-in/welt/jetted) / Applied(patch)
    • pocket_projection: Flat(평평하게 붙음) / Projected(몸판에서 떠 있으나 독립 3D 볼륨은 아님) / Volumetric(독립 3D 볼륨: gusset/bellows/box/pouch/cargo)
  • 금지 추론: 플랩이 보인다고 해서 Applied·Projected·Volumetric가 되지 않는다. Applied 포켓이 자동으로 Projected나 Volumetric인 것도 아니다. 반대로 자체 gusset/bellows 3D 몸체가 있는 포켓(예: cargo)은 Volumetric이므로 Projected로 낮춰 읽지 않는다.
  • 다수성: 개수는 메타데이터다. count(이산 반복)와 density(sparse|moderate|dense, 분산 정도)로 적고, 별도 파라미터로 만들지 않는다.
  • POCKET MORPHOLOGY STATE: pocket = Present이면 보고하는 모든 포켓 항목에 construction과 projection을 반드시 답한다. 이 답은 각 pockets 항목 안에 들어간다.
    • 판독 가능 → OBSERVED + canonical 값. 생략하거나 하향 판독하지 않는다.
    • 증거가 가려짐 → NOT_VISIBLE, value null. 손·팔·물체가 가리는 경우, 개구부나 몸체가 차폐된 경우, 크롭 밖인 경우, 봐야 할 부위(개구부 가장자리·솔기·측면 깊이)가 화면에 없는 경우가 해당한다.
    • 부위는 보이지만 값을 확정할 수 없음 → UNKNOWN, value null. set-in과 patch를 구분할 수 없거나 측면 깊이가 안 보여 돌출 정도를 알 수 없는 경우다.
    • 판정은 파라미터마다 독립이다. 예를 들어 construction은 NOT_VISIBLE, projection은 UNKNOWN일 수 있다.
    • UNKNOWN은 어려운 판단을 피하는 용도가 아니다. 판독 가능한데 UNKNOWN을 고르면 값을 지어내는 것과 똑같은 계약 위반이다.
    • pocket이 Present가 아니면 형태를 아예 보고하지 않는다. 이는 '불확실'이 아니라 '해당 없음'이다.
  • POCKET INSTANCES: 포켓 형태는 pocket 관찰 안의 pockets 배열로만 보고한다.
    • 각 항목은 location + construction + projection을 함께 담아 짝이 흩어지지 않게 한다(Chest/Applied/Flat, Lower Front/Applied/Volumetric JSON 예시가 있다).
    • Present면 포켓이 하나든, 동질 세트든, 서로 다른 그룹이든 항상 pockets를 출력한다.
    • 구분 가능한 포켓 그룹당 한 항목을 쓴다. 단일 포켓이나 하나로 이어진 파우치는 한 항목이다.
    • 그룹은 보이는 것으로만 나눈다. 의류 이름("Cargo", "utility", "tactical")은 항목을 늘릴 근거가 아니다.
    • LOCATION 토큰은 네 개뿐이다: Chest(상단 앞 가슴 높이), Lower Front(하단 앞, TROUSER의 앞 힙 포켓 포함), Sleeve, Leg(trouser/jumpsuit 다리). Side/Back/Left/Right/Hip/Thigh, 자유 텍스트, 좌표는 금지다.
    • 좌우 대칭은 인스턴스를 나누는 기준이 아니다. 같은 형태의 좌우 포켓은 한 항목이고, 단일 포켓을 둘로 쪼개지 않는다.
    • pockets는 개수가 아니다. 가림 때문에 전부 보이지 않을 수 있으므로 항목 수를 포켓 수로 취급하지 않는다.
    • 항목별 construction/projection에도 위와 같은 상태 규칙을 파라미터별·인스턴스별로 적용한다.
    • 항목을 지어내지 않는다. 포켓은 보이지만 그룹을 나눌 수 없으면 보이는 범위를 덮는 한 항목으로 쓴다.

  • evidence_id는 레코드 내 고유하고 안정적이어야 한다. source_observation_refs는 예 "observations.graphic"이며, 해당 관찰이 없으면 DM_SPECIFIC_OBSERVATION.

  • 디테일이 없으면 "evidence": []. DM 점수, DM1~DM9, tier, "M1/M2 triggered", Direction, Strength 등은 절대 출력하지 않는다.
