STAGE 2 · B

적용성 결정 — 어떤 키를 낼 것인가

키를 생략하는 것은 "해당 없음"을 뜻하는 계약입니다. "안 보임"을 생략으로 표현하면 안 됩니다.

NOT-APPLICABLE

카테고리별 금지 키 → 키 자체를 생략

ABSENT·None·N/A·null로도 내보내면 안 됨. 예: Trouser의 closure_type, Jacket의 shoulder_span, 상의의 silhouette.

REQUIRED KEYS

카테고리별 필수 키 → 반드시 존재

없는 특징도 None/ABSENT로 답함. 개수: T-Shirt·Shirt 19 · Sweater·Sweatshirt 20 · Jacket·Coat·Jumpsuit 21 · Trouser·Skirt 14 · Dress 23.

CONDITIONAL TRIGGERS

부모 관찰이 켜면 반드시 따라 나오는 키

  • front_opening_extent = Partial/Full → closure_type (Jacket/Coat는 항상 필수) #2
  • sleeve ≠ Sleeveless → cuff_type, sleeve_volume
  • cuff_type ≠ None → cuff_scale (None이면 키 생략)
  • collar ≠ None → collar_scale
  • 스트랩·스트랩리스·홀터·원숄더가 보이면 → shoulder_connection #4
  • waist_definition: 게이트1 Jacket/Coat/Dress/Jumpsuit · 게이트2 Jacket이 Cropped/Waist Length면 제외 #3
개선 #2앞트임 없는 아우터의 closure_type Jacket/Coat에서는 필수인데 값 도메인에 None이 없어, 앞트임이 없는 아노락(front_opening_extent=None)에 쓸 정상 답이 없다. 아우터에서도 Partial/Full일 때만 쓰는 조건부 키로 바꾸거나, 이 경우 ABSENT를 쓴다고 명시한다.
개선 #3waist_definition 필수 여부 불일치 게이트 2에서 Coat/Dress/Jumpsuit는 항상 대상이고 최종 스윕 (7)도 키를 요구하는데, REQUIRED KEYS 목록에는 없다. Coat/Dress/Jumpsuit의 필수 목록에 넣고 Jacket만 조건부로 남긴다.
개선 #4스트랩리스·민소매 드레스의 shoulder_drop / shoulder_structure Dress에서 둘 다 필수인데 판단할 어깨선이 없다. 그러면 None이 "확인했더니 없음"이 아니라 "해당 없음"으로 오염된다. shoulder_connection이 Strapless·Halter·One Shoulder·Strap이면 키를 생략하는 규칙을 둔다.
