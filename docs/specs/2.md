# 크리에이터 태그 분석 내부 API (stmx-biz)

## 배경과 목적
크리에이터가 의류·잡화 태그를 촬영하면 브랜드와 상품을 알아내 구매 가능한 판매 링크를 찾아 주는 기능의 분석 단계입니다. Anthropic 키(`lib/style-ex/api-key.ts`)와 네이버 쇼핑 검색(`lib/playground/naver-search.ts`)이 이 프로젝트에 있으므로 분석과 후보 검색을 여기서 맡고, stmx-web 서버가 내부 API로 호출합니다.

현재 코드에서 확인한 제약:
- `search.shopping.naver.com` 카탈로그 페이지는 서버 요청 시 418로 막혀, 상품 이미지의 공식 경로는 네이버 쇼핑 검색 API입니다(`naver-search.ts` 주석).
- `proxy.ts`의 matcher는 `/api`를 제외하므로 내부 API는 라우트에서 직접 인증해야 합니다. 패턴은 `app/api/internal/style-id-queue/route.ts`의 Bearer + `timingSafeEqual`입니다.
- `brands`는 `display_name`, `naver_brand_name`, `aliases`, `source`, `is_active` 열을 갖습니다.

## 범위
### 하는 것
- 태그 사진 분석 + 판매 후보 검색 내부 API
- 수정된 텍스트로 재검색하는 내부 API
- 관리자 브랜드 목록에서 태그로 자동 등록된 브랜드를 걸러 보는 기능

### 하지 않는 것
- `brands`, `products`, `affiliate_links` 쓰기(stmx-web 담당)
- 쇼핑몰 HTML 크롤링, 이미지 재호스팅
- 태그 사진 저장, 사진·응답 원문 로그
- 재고·결제 가능 여부의 실시간 확인

## 변경할 동작
1. `lib/creator-tag/`(신규)에 다음을 둡니다.
   - `extractTag(image)`: `anthropicClientOptions()`와 `visionModel()`을 재사용해 태그 사진 1장에서 `brandName`, `productName`, `styleCode`(품번), `barcode`, `confidence`(0~1)를 추출합니다. 사진 속 글자는 데이터로만 취급하고, 지시문으로 따르지 않도록 프롬프트에 명시합니다. 출력은 zod로 검증하고, 읽지 못한 필드는 null입니다. 호출 제한 시간은 60초입니다.
   - `findBrand(name)`: NFKC 정규화, 소문자화, 문자·숫자 외 제거 후 `display_name`, `naver_brand_name`, `aliases`와 완전 일치로 찾습니다. `is_active=false` 브랜드도 대상입니다.
   - `findCandidates(input)`: 아래 순서로 `searchShopping`을 호출해 결과를 모읍니다. 쿼리는 값이 있는 것만 만들고, 누적 후보가 5개가 되면 중단하며, 최대 3회 호출합니다.
     1. `브랜드 + 품번`
     2. `브랜드 + 상품명`
     3. `바코드`
2. `ShopItem`과 `searchShopping`에 네이버 응답의 `brand`, `maker`를 추가합니다. 기존 호출부의 동작은 바꾸지 않습니다.
3. 후보 필터(모두 만족):
   - URL이 `https://smartstore.naver.com/.../products/<숫자>` 또는 `https://brand.naver.com/.../products/<숫자>` 형식
   - `productType`이 1~3 (중고·단종·판매예정 제외)
   - `productId`, `title`이 비어 있지 않음
   - 브랜드를 알면 정규화한 `brand`, `maker`, `title` 중 하나에 브랜드명 또는 별칭이 포함됨
4. 후보 정렬: 품번이 제목에 포함된 것 → 브랜드 필드 일치 → 네이버 검색 순서. `productId` 기준 중복을 제거하고 최대 5개를 반환합니다.
5. 관리자 API `GET /api/admin/brands`에 `source` 열과 `source` 쿼리 필터를 추가하고, `app/admin/brands/page.tsx`에 '태그 등록(creator_tag)' 필터와 표시를 추가합니다. `types/admin.ts`의 `AdminBrand`에도 `source`를 추가합니다.

## API 계약
공통 인증: `Authorization: Bearer $CREATOR_TAG_INTERNAL_SECRET`. 환경변수가 없거나 값이 다르면 401입니다.

### POST /api/internal/creator-tag/analyze
요청: `multipart/form-data`, `image`(JPG/PNG/WEBP, 5MB 이하)

### POST /api/internal/creator-tag/search
요청: `application/json`
```json
{ "brandName": "string", "productName": "string|null", "styleCode": "string|null", "barcode": "string|null" }
```
`brandName`은 1~100자, `productName`은 300자 이하, `styleCode`와 `barcode`는 64자 이하입니다. `productName`, `styleCode`, `barcode`가 모두 비면 400입니다.

### 두 API의 200 응답
```json
{
  "extracted": { "brandName": "string|null", "productName": "string|null", "styleCode": "string|null", "barcode": "string|null", "confidence": 0.0 },
  "brand": { "id": "uuid", "displayName": "string" },
  "candidates": [
    { "productId": "string", "title": "string", "brandName": "string|null", "imageUrl": "string|null", "price": 0, "mallName": "string", "purchaseUrl": "https://smartstore.naver.com/.../products/123" }
  ]
}
```
- `brand`는 미등록이면 null, `candidates`는 없으면 빈 배열입니다.
- `/search`의 `extracted`는 입력값이고 `confidence`는 null입니다.
- `price`는 원 단위 정수이며 모르면 0입니다.

오류: `{ "error": "string" }`. 400 입력 오류, 401 인증, 413 크기 초과, 415 형식 오류, 422 태그 판독 불가(브랜드·상품명·품번·바코드 전부 null), 503 Anthropic 또는 네이버 설정·호출 실패.

## 수용 기준
- [ ] 인증 헤더가 없거나 틀리면 두 내부 API가 401을 반환하고, `CREATOR_TAG_INTERNAL_SECRET` 미설정 시에도 401을 반환한다.
- [ ] 5MB 초과 이미지는 413, 지원하지 않는 형식은 415를 반환한다.
- [ ] 브랜드·상품명·품번·바코드를 모두 읽지 못하면 422를 반환한다.
- [ ] `NIKE`, `nike`, ` Ni-ke `는 같은 브랜드 키로 정규화되고, `aliases`에 있는 이름으로도 기등록 브랜드를 찾는다.
- [ ] 후보의 `purchaseUrl`은 모두 smartstore 또는 brand.naver.com의 `/products/<숫자>` 주소이고, 카탈로그·외부 몰 URL은 제외된다.
- [ ] `productType` 4 이상 항목은 제외된다.
- [ ] 브랜드가 다른 항목은 제외되고, 품번이 제목에 포함된 후보가 먼저 정렬된다.
- [ ] 응답 후보는 최대 5개이고 `productId`가 중복되지 않는다.
- [ ] 네이버 호출은 요청당 최대 3회이다.
- [ ] 두 내부 API는 `brands`, `products`, `affiliate_links`에 쓰지 않는다.
- [ ] 태그 이미지와 Vision 응답 원문이 저장되거나 로그에 남지 않는다.
- [ ] `/api/admin/brands?source=creator_tag`는 해당 source의 브랜드만 반환하고, 관리자 화면에서 같은 필터를 쓸 수 있다.
- [ ] 기존 `searchShopping` 호출부의 동작과 타입 검사가 유지된다.

## 가정
- '크롤링'은 차단과 약관 위험을 피하기 위해 네이버 쇼핑 검색 API의 이미지·링크 사용으로 대체합니다.
- 구매·결제 가능 페이지는 스마트스토어와 네이버 브랜드스토어 상품 페이지로 한정합니다.
- Vision 모델은 기존 `visionModel()` 설정을 재사용합니다.
- 바코드는 Vision이 읽은 숫자를 검색어로만 사용하고 별도 바코드 DB는 연동하지 않습니다.
