비용 비교: Claude Code CLI vs Anthropic API (10,000벌)

2.1. Claude Code CLI 사용 시 1,120만 ~ 2,100만 원+

Claude Code는 개발용 대화형 에이전트 CLI로, 대량 배치 추출에 적용 시 구조적 비효율로 비용이 폭증합니다:

  • 시스템 프롬프트 오버헤드: 도구 정의(Bash, Read, Edit 등), 안전 수칙 등 고유 시스템 프롬프트만 매 턴 15,000 ~ 20,000 토큰 고정 주입.
  • 다중 턴 컨텍스트 누적: 스크립트 실행, 이미지 조회 등 도구 호출 순환마다 이전 대화 이력이 누적되어 건당 100,000 ~ 150,000 토큰으로 급증.
  • 캐싱 및 배치 할인 제어 불가: 프롬프트 캐싱 위치의 세밀한 제어가 어렵고, 50% 할인되는 Batch API 적용 불가.
  • Rate Limit 물리적 차단: Pro/Team 구독 플랜은 5시간당 호출 횟수 제한으로 10,000건 연속 처리가 물리적으로 불가능.
건당: 약 $0.80 ~ $1.50+ ➔ 10,000벌: 약 $8,000 ~ $15,000+

2.2. Anthropic API 직접 호출 케이스 시나리오별 실측

Case 1. 일반 API 호출 (정가, 캐싱 미적용)
• 관찰: 입력 $0.340 + 출력 $0.083 = $0.423
• 판정: 입력 $0.056 + 출력 $0.100 = $0.156
➔ 건당 $0.58 (약 810원) / 10,000벌: $5,800 (약 812만 원)
Case 2. 현재 구현 (관찰 프롬프트 캐싱 적용)
• 68k 관찰 프롬프트 5분 내 0.1배 할인($0.50/1M) 적용
• 관찰 입력이 $0.340 ➔ $0.039로 대폭 감소
➔ 건당 $0.28 (약 390원) / 10,000벌: $2,770 (약 388만 원)
Case 3. 관찰 + 판정 프롬프트 모두 캐싱 적용
• 판정 프롬프트(12k) 캐싱 시 판정 입력 $0.056 ➔ $0.013 감소
➔ 건당 $0.23 (약 320원) / 10,000벌: $2,340 (약 328만 원)
Case 4. Message Batches API (50% 비동기 할인) + 캐싱
• 24시간 비동기 처리 Batch API: 모든 입출력 단가 50% 추가 할인
➔ 건당 $0.12 (약 165원) / 10,000벌: $1,170 (약 164만 원)

Gemini 1.5 Flash 전환 시 소요 시간 벤치마크 (10,000벌)

4.1. 1건당 처리 속도 산출 근거

지표 실측 / 산출값 기술적 세부 내역
초기 응답 속도 (TTFT) 약 0.5 ~ 0.8초 68,000 토큰 관찰 프롬프트에 Context Caching 적용 시 첫 토큰 즉각 반환
생성 속도 (TPOT) 초당 150 ~ 250 토큰 고속 경량 VLM 아키텍처로 대용량 JSON 스트리밍 출력
1건당 순수 소요 시간 평균 약 11 ~ 14초 37개 파라미터 JSON 생성 (약 10~13초) + 로컬 스코어링 및 판정 (약 0.5초)

4.2. 실행 아키텍처별 10,000벌 총 소요 시간 비교

실행 아키텍처 방식 분당 처리량 10,000벌 총 소요 시간 특징 및 운영 권장
1. 비동기 병렬 워커 풀
(25~30개 동시 요청)		 약 120 ~ 125건 / 분 약 1시간 20분 ~ 2시간 즉각적인 결과 확인이 필요할 때 최적
2. Gemini Batch API
(batchGenerateContent)		 클라우드 분산 약 1시간 ~ 4시간
(SLA: 최대 24시간)		 정기 대규모 배치 최적
(50% 추가 할인, 완전 무인 백그라운드)
3. 단순 순차 단일 루프 약 5건 / 분 약 30 ~ 33시간 비추천 (네트워크 단절 위험)

실행 방식 기술 상세 분석:

  • 비동기 병렬 워커 풀 (Node.js / Python 스크립트): 25~30개의 워커가 동시 요청을 전송. 12초마다 25건 완료 시 초당 약 2건(분당 약 125건). 10,000건 ÷ 125건/분 = 80분. 지수 백오프(Exponential Backoff) 및 재시도를 고려해도 2시간 이내 완료.
  • Google Gemini Batch API (강력 추천): 10,000건의 이미지 URL과 관찰 프롬프트가 담긴 .jsonl 파일을 생성하여 1회 업로드. 로컬 서버 프로세스를 계속 켜둘 필요 없이 Google 클라우드 자원으로 일괄 처리 후 결과 다운로드 (실측 보통 1~4시간 내외 완료).

4.3. 대규모 배치 시 필수 체크리스트

1 Context Caching 등록

68k 토큰 관찰 프롬프트를 cachedContents.create로 사전 등록 후 배치 요청 시 해당 ID를 참조해야 속도 3배 향상 및 비용 90% 이상 절감.

2 이미지 페이로드 최적화

Base64 인라인 인코딩 대신 Supabase 스토리지 또는 웹 Public URL을 직접 전달하여 네트워크 대역폭 병목 방지.

3 Bulk DB Insert

로컬 scoring.ts로 Style ID 도출 후 PostgreSQL product_style 테이블에 1,000건 단위 청크 벌크 삽입.

★ 엔지니어링 최종 제언 (Recommended Next Step)

10,000벌 의상 스타일 추출 시 방안 B (Google Gemini 1.5 Flash + Batch API)를 채택할 것을 강력 권장합니다. 비용은 기존 812만 원에서 약 4만 ~ 7만 원으로 99.4% 절감되며, 소요 시간 또한 1~2시간 내외로 완료할 수 있어 압도적인 운영 효율을 달성할 수 있습니다.
