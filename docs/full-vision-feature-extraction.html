(a) SVP-001 look_observability CONTROL

(b) 이 물체가 주인공의 착장 실현에 참여하는가?

개선 #8grammar 정의 없음 Jacket · Coat에 묻지만 Tailored / Casual / Utility를 가르는 기준이 한 줄도 없고, §0의 "스타일 판단 금지"와도 부딪힌다. 테일러드 라펠·어깨 구조, 패치 포켓·플랩·스톰 플랩 같은 구성 근거로 정의해 관찰 사실로 만든다.(원문: “SVP-101 grammar — What garment grammar is it (tailored / casual / utility)? Values: Tailored · Casual · Utility.”)
개선 #9fit 경계 정의 없음 알려진 제약 L-1: 모델이 fit을 기준보다 한 단계 헐겁거나 꽉 끼게 읽고, M178에서는 그것만으로 TC의 SIL-TRUE-OVERSIZED가 켜진다. Slim / Regular / Relaxed / Oversized의 경계(어깨선 · 몸판 여유 · 주름의 방향)를 짧게 정의하고, 경계에서 망설이면 UNKNOWN을 허용한다.(원문: “SVP-104 fit — How does the garment product fit the body? Values: … Slim · Regular · Relaxed · Oversized …” / KNOWN_LIMITATIONS L-1 “The model can read fit one step looser or tighter than the reference.”)

Present면 묶음마다 한 항목(한 개 · 같은 한 쌍 · 캥거루 주머니 = 각 1). location은 네 토큰만. 형태를 못 읽어도 항목은 남기고 state NOT_VISIBLE/UNKNOWN + value null. 117 · 118을 따로 내지 않음.

개선 #5shoulder_drop은 묻지만 대부분 버려짐 §6은 상의 모두에 shoulder_drop을 내라고(“Do not leave shoulder_drop out”) 하지만, 추출 엔진은 SR 지배 상의(가장 바깥 상의)의 값만 저장하고 나머지는 버린다(알려진 제약 L-4, AXIS-DEMAND-CONDITIONAL). 모델에게 "가장 바깥 상의의 shoulder_drop만 필수"라고 좁히거나, 다른 의복의 값도 TC 등에서 쓰도록 수요를 넓힌다. 지금은 토큰과 주의를 쓰고도 결과에 남지 않는다.(원문: “Do not leave shoulder_drop out of the shoulder look.” / KNOWN_LIMITATIONS L-4 “shoulder_drop (SR) is stored only for the SR governing upper component.”)
SLIT · 구조 관찰에서 (Skirt · Dress)

밑단의 설계된 트임이 분명히 보일 때만 Present

밑단이 충분히 보여 트임이 없다고 확신할 때만 None. 그 외는 NOT_VISIBLE(가려짐·잘림) 또는 UNKNOWN. 보이는 다리·피부, 포즈로 생긴 벌어짐, 풀린 플래킷, 랩 겹침은 슬릿이 아님. "슬릿이 안 보인다"를 None으로 바꾸지 않음.

E/I · T/C · S/R · D/M

엔진이 RESOLVED면 그 글자, 미결이면 양쪽 글자(OR). DM은 Full-Look 엔진이 없어 늘 D 또는 M이라 후보가 최소 2개입니다(예: ETRD · ETRM). 패킷의 dm_evidence는 관찰 결과 탭에서 볼 수 있습니다.

0. ROLE AND LIMITS

  • 사진 한 장 속 완성된 착장 하나의 원시 물리 관찰자. 몸 위에 보이는 것만 보고함.
  • 점수 · 순위 · 스타일 판단 · 스타일 방향 · 브랜드 추정 · 보이지 않는 것의 추론 금지.
  • 파일명 · 캡션 · 이미지 속 글자 · 워터마크 · 메타데이터는 증거가 아님.
  • 착장 사진이 아니면(플랫레이 · 상품 사진 · 마네킹 · 콜라주) not_a_worn_look을 적고 멈춤. #2

1. OBSERVATION STATE ENVELOPE (every fact)

  • 사실마다 상태 하나: OBSERVED(값 있음) · ABSENT(담는 부분은 보이는데 현상이 없음) · NOT_VISIBLE(가려짐 · 잘림 — limitation 필수) · UNKNOWN(보이지만 확정 불가).
  • UNKNOWN을 피하려고 값을 지어내지 않음. NOT_APPLICABLE은 저장 상태가 아님 — 적용되지 않는 사실은 내지 않음.

2. PROCEDURE — ONE INTEGRATED OBSERVATION

  • 이미지를 한 번 읽고 정리 순서만 G1→G4. 여러 패스가 아니고, 특정 축을 위해 다시 보지 않음.
  • G1 프레임 판독성 + 참여 물체 등록(c1…, 한 물체 = 한 컴포넌트) + 제외 목록 + 정체. 판독성은 읽는 곳에서 사실마다 기록.
  • G2 컴포넌트마다 표면을 한 번: 색 → 외관 6사실. DM 시스템도 이 사실로 이름 붙임.
  • G3 의복마다 구조: 형태 사실, 그리고 어깨 · 앞판 · 포켓 영역을 각각 한 번. 슬릿도 여기서. 제품 구조와 착용 결과는 다른 필드.
  • G4 입은 상태: 가장 바깥 상의의 relation/shoulder/shape, 레이어 · 조임 관계, 노출, G2 색의 field/point standing. #3
  • (e) 다른 이미지의 기억이나 패션 지식으로 채우지 않음. 같은 사실의 두 번째 언급은 재사용이지 재관찰이 아님.

3. COMPONENT IDENTITY

  • 의복은 Item 카테고리 10개만. 맞는 게 없으면(케이프 · 판초 · 브라톱 …) UNKNOWN으로 두고 색 · 외관만 — 가까운 카테고리로 억지로 맞추지 않음.
  • 액세서리는 family 10개(+ other · UNKNOWN). footwear는 product_family와 조건부 subtype, 다른 family는 확실할 때만 subtype.
  • 상품 맥락(General / Activewear-Performance)은 내지 않음. 컴포넌트 안에 participation · eligible · excluded 필드를 내지 않음. #1

4. COLOUR (per component; firewall)

  • 색 영역 = carrier + family(21) + lightness + effect + standing(field / point + 점이면 contrast).
  • 부품 색(단추 · 버클 · 무늬색 · 끈 · 패널)은 같은 컴포넌트의 point — 별도 컴포넌트가 아님.
  • 금속 방화벽: 금 · 은은 가진 물체에 metallic로. 한 물리 현상을 두 carrier에 중복하지 않음.
  • 피부 · 머리 · 배경은 색 영역이 아님. 그림자 · 반사 · 작은 면으로 못 읽으면 unreadable.

5. STYLE-OWNED RELATIONS (12 Style Vision parameters)

  • SVP-001–012의 질문 · 값 · 적용 · 상태를 정의: 프레임, 정체, 세분, 앞 상태, 색, 색 standing, 최종 상의 relation · shoulder · shape, 레이어, 조임, 노출.
  • Rules: 앞 상태는 앞트임 의복만. 조임은 실제로 끌어당길 때만 OBSERVED, 얹혀만 있으면 ABSENT. 자기 끈 벨트는 own device이고 별도 컴포넌트가 아님. #4
  • 최종 상의 3개는 가장 바깥 상의를 입은 상태로, 그 의복의 fit · shoulder_structure와 별개. #7
  • 노출: Class A 신체 부위 / Class B 설계된 개구부. 부위 ≠ 메커니즘 — 라벨(미니 · 홀터 · 슬릿 · 민소매)만으로 부위를 정하지 않고 실제로 보이는 피부만. 크기 · 정도는 판단하지 않음. 실현 하나 = 기록 하나.

6. ITEM RAW FACTS (26 Item Vision V1_3 facts reused verbatim)

  • 카테고리별 적용성 표 — 표에 있는 사실만 냄. 액세서리 · UNKNOWN 물체는 외관 6사실만.
  • SVP-101–126의 값 도메인(카테고리별 fit · length · silhouette 포함). #8 #9
  • 어깨는 한 번 보고 structure · drop · span · connection을 답하고, 최종 상의 shoulder도 그 관찰에서. structure와 drop은 서로에게서 유도하지 않음. 가려지면 NOT_VISIBLE. #5
  • 벨트 방화벽: 자기 벨트는 attachment Belt, 별도 벨트는 belt 컴포넌트.
  • 포켓: pockets[]가 유일한 형태 저장소 — 묶음마다 한 항목, location 네 토큰, 못 읽으면 항목은 남기고 state + null. 117 · 118을 따로 내지 않음.
  • 슬릿: Skirt · Dress만. 분명히 보일 때만 Present, 확신할 때만 None, 그 밖은 NOT_VISIBLE / UNKNOWN.
  • 조건부: sleeve_volume(소매 있음), closure_type(앞트임 있음, Jacket · Coat는 늘), waist_definition(Cropped · Waist Length가 아닌 Jacket · Coat · Dress · Jumpsuit).

7. UNKNOWN POLICY

  • UNKNOWN은 정당한 답 — 보이지만 해상도 · 포즈 · 조명으로 확정할 수 없을 때. 가려지면 NOT_VISIBLE, 보이는데 없으면 ABSENT.
  • 안전하려고 읽을 수 있는 사실을 UNKNOWN으로 낮추지 않고, 완결하려고 추측을 OBSERVED로 올리지 않음.

8. OUTPUT

  • JSON 객체 하나(frame · objects · front_state · layer_relations · securing_relations · colour_areas · upper · exposure_supplement · facts). 설명 · 마크다운 · 점수 · 방향 · 판정 · 스타일 이름 · 축 글자 · 숫자 평가 금지.

8a. EXACT OUTPUT SHAPE

  • 각 블록의 정확한 키와 값 모양. objects에 participates · product_family · subtype · attached_to · why.
  • securing_relations는 별도 장치형과 own-device형 두 모양. colour_areas는 읽은 색 / 못 읽은 색 두 모양.
  • facts는 ref → 사실 → 값 · 배열 · "ABSENT" · "UNKNOWN" · NOT_VISIBLE 객체 · pocket 객체.
  • dm_subsystem에는 look_detail_systems만. 블록 끝마다 설명 주석이 붙어 있음. #6

8b. STATE SEMANTICS

  • "None" 토큰(asymmetry · pocket · shoulder_drop · collar · slit · shoulder_structure)은 OBSERVED이지 ABSENT가 아님.
  • ABSENT는 None 토큰이 없는 사실(외관 6 · 노출)에만. 내지 않은 사실은 UNKNOWN으로 읽힘 — 적용되는 사실은 모두 냄.
  • material · surface · decorative_detail · attachment는 MULTI(배열). Present 포켓은 pockets[]가 있어야 완결.
  • "black은 dark로 읽는다"(CDM-08)는 철회됨 — lightness는 보이는 대로.

8c. OUTPUT FORMAT

  • 날 텍스트 JSON: 첫 글자 {, 마지막 글자 }. 코드 펜스 · 라벨 · 앞뒤 설명 · 감싼 객체 · 주석 금지. 객체 정확히 하나.

8d. COMPONENT IDENTITY VERSUS ATTRIBUTE VISIBILITY

  • 정체는 보이는 부분으로 정함(립 니트 터틀넥 칼라 → Sweater, 직물 칼라 + 단추 플래킷 → Shirt). 대부분 가려져도 OBSERVED.
  • 가려진 속성은 정체를 낮추지 않음 — 각 사실을 자기 상태(NOT_VISIBLE + limitation, 구분 안 되는 소재 · 표면은 UNKNOWN)로.
  • 정체 UNKNOWN은 어느 카테고리에도 맞지 않거나 두 카테고리가 똑같이 지지될 때만. "조금만 보임"은 이유가 아님.

8e. INTEGRATED SELF-BELT

  • 의복에 속한 벨트 · 타이 · 새시(자기 고리 · 봉제 · 자기 여밈 끈)는 그 의복의 일부 — objects · 색 carrier · 액세서리가 아님. 색 · 소재가 달라도 마찬가지.
  • 자기 버클이나 독립된 띠가 있는 별도 물체일 때만 belt 컴포넌트.
  • 기록: attachment Belt, 색은 그 의복의 point(part attachment/Belt), waist_definition Cinched(끌어당김) · Defined(조이지 않고 형태만) · Undefined.
  • 조임은 securing_relations에 own-device 항목 하나로 한 번만. SVP-011의 "own belts → SVP-119"는 이 규칙으로 읽음. #4

9. FROZEN FULL-LOOK DM EVIDENCE

  • 이미 관찰한 G2 표면 사실과 G4 관계로만 디자인 디테일 시스템을 기록. 다시 보지 않고, 컴포넌트를 다시 식별하지 않고, DM 점수 · 방향 · 강도를 정하지 않음. #10
  • 카테고리 · 소재 이름 · 공정 이름(워싱 · 염색 · 디스트레스) · 액세서리 유무 · 개수로 디테일을 추론하지 않음.
  • 시스템마다 carrier_refs · family A–J · (H면) relational_form · size · contrast · position(각 state) · repeated_units. []는 "관찰한 것이 없음"이지 "디테일 없음"이 아님.
  • look_components · dm_evidence_visibility는 내지 않음(코드가 조립) — 내면 계약 위반.
  • family A–J 정의와 "그 자체로는 디테일이 아닌 것" 목록(광택 · 투명 · 노출 · 슬릿 · 실루엣 · 레이어링 · 개수 · 평범한 색 차이 …).
